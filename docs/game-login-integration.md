# 게임 로그인 회원 정보 수신

게임 서버가 로그인을 검증한 후 호출하는 서버 간 API입니다. 게임 비밀번호는 받지 않습니다.

## 설정과 요청

대시보드 `.env`에 `GAME_SERVER_API_KEY`를 설정하고 게임 서버에도 같은 비밀 키를 설정합니다. 빈 값이면 수신 API는 503으로 비활성화됩니다. Unity 클라이언트에 키를 넣지 않으며 운영에서는 HTTPS를 사용합니다.

`POST /api/game/player-login` (끝 슬래시 없음)

```http
Authorization: Bearer <GAME_SERVER_API_KEY>
Content-Type: application/json
```

```json
{"member_id": "member-001", "display_name": "플레이어 이름"}
```

`member_id`는 인증된 게임 회원의 변경되지 않는 고유 ID입니다. 최대 120자이며 영문·숫자·`_-.@`만 허용합니다. 닉네임이나 변경 가능한 로그인명은 사용하지 마세요. MySQL collation에 따라 대소문자가 동일시될 수 있으므로 대소문자만 다른 ID를 발급하지 마세요. `display_name`은 1~80자입니다. 두 필드만 허용하고 본문은 최대 4KB입니다. 비밀번호, 역할, 토큰 등은 보내지 않습니다.

## 응답과 연결

최초 등록은 201, 재로그인·재시도는 기존 플레이어를 반환하며 200입니다. 표시 이름은 갱신됩니다.

```json
{
  "player": {
    "player_id": "00000000-0000-0000-0000-000000000001",
    "member_id": "member-001",
    "display_name": "플레이어 이름",
    "source": "live"
  },
  "created": true
}
```

게임 서버는 응답의 `player_id`를 회원과 연결해 보관합니다. 내부 외부 ID는 `game:member:<member_id>`입니다. 클라이언트가 임의로 전달한 ID를 신뢰하지 말고 인증된 회원에서 ID를 가져오세요. 관리자 계정이나 웹 인증 세션은 생성하지 않습니다. 기존 device/legacy 플레이어는 자동 병합하지 않습니다.

| 상태 | 의미 |
| --- | --- |
| 400 | JSON·필드 검증 실패 |
| 401 | 서버 인증 키 누락·불일치 |
| 405 | POST 이외의 요청 |
| 409 | 같은 외부 ID의 데모 레코드 충돌 |
| 413 | 본문 크기 초과 |
| 415 | JSON Content-Type 필요 |
| 503 | 서버 키 미설정 |

연결 실패·5xx는 게임 서버에서 재시도 큐 등으로 처리하세요. 동일 회원 재전송은 중복 플레이어를 만들지 않습니다. DB 연결 실패 시 성공 응답을 반환하지 않습니다.

이 API의 수신 범위는 회원 식별 정보와 플레이어 연결입니다. 게임 세션·행동 이벤트는 [별도 MongoDB 수집 API](mongodb-integration.md)의 `/api/game/records`로 전달합니다. 로그인 이력 누적과 회원 탈퇴·병합은 별도 연동 범위입니다. 실제 플레이어 목록에는 표시되지만 플레이 기록 전에는 학습 지표가 없습니다.
