# 관리자 게임 분류와 집계 기준

2026-11-10 중간보고서 09장(게임 구성)의 4분야 24종 목록을 `telemetry/catalog.py`의 읽기 전용 카탈로그에 반영했다. 공개 홈페이지, 게임 코드, DB 저장 구조 및 적재 검증 규약은 변경하지 않는다.

- 자료구조 10종: ST01, ST02, ST03, ST04, ST05, DS09, ST07, ST08, DS10, ST10
- 알고리즘 6종: ALG02, ALG01, ALG03, ST06, ST09, ALG04
- SQL 4종: SQL01~SQL04
- 데이터 탐색 4종: DATA01~DATA04

게임 분류는 `game_problems.task_id`와 실행 ID의 대소문자 무시 완전 일치만 사용한다. 임의 접두사·제목·기존 `topic`으로 연결하지 않는다. 예를 들어 `stack-pop-test`는 ST03으로 추측하지 않고 미분류로 남긴다. 기존 데이터는 그대로 보존하며 전체 집계에 포함한다. 실제 송신 ID가 다른 경우 확인된 대응표를 먼저 합의해야 한다.

`category`(structures/algorithms/sql/data)와 `game_id`(실행 ID) 필터는 관리자 조회 기능이다. 기존 topic 필터는 호환 유지한다. 게임별 저장 주제 확장과 수신 이벤트 스키마 변경을 자동으로 승인하거나 수행하지 않는다. 보고서에 적힌 게임의 details 누락·v1/v2 어휘 불일치는 이 UI 수정으로 해결되지 않는다.

분야/게임 필터는 문제 정의 → 실행 → 관련 세션/이벤트에 적용되며 CSV에도 같은 조건을 사용한다. 전체 종합에는 미분류 기록이 포함된다. 분야·게임을 선택하면 해당 실행 ID의 기록만 포함한다. 관측 게임 수는 선택된 실행 코호트 기준이며 수집 완성도나 출시 상태가 아니다.

문제 해결률은 completed 실행 / 전체 실행이며 진행 중도 분모에 포함한다. 완료·포기 기록이 전혀 없을 때 주의 문구와 진행 중 건수를 보여준다. 시간은 완료된 실행 중 active_ms가 있는 기록만 평균한다. 힌트 0건은 hint 이벤트가 없다는 뜻이지 미사용을 보장하지 않는다. 연산 성공을 문제 완료로 변환하거나 DB 상태를 수정하지 않는다.
