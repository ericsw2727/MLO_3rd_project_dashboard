회원 정보는 MySQL, 학습 기록은 MongoDB에서 조회합니다. 24종 게임 등록과 실제 기록 관측, 종단 연동 완료는 서로 다른 상태입니다. 데모는 합성 데이터이며 실제 학습 효과나 능력 진단이 아닙니다.
01 / TIME SERIES

활동량과 해결 흐름

문제 실행이 시작된 날의 시작·해결·포기 수를 봅니다. 특정 날짜의 변화는 콘텐츠·운영 변경을 확인할 단서입니다.

해결은 현재까지의 결과이므로 같은 날짜에 실제로 발생한 해결 이벤트 수와 다릅니다.

02 / OUTCOME & TOPIC

결과 구성과 학습 분야별 차이

해결률 = 해결된 실행 / 시작한 실행. 진행 중과 포기도 분모에 포함합니다. 레이더의 축은 동일한 해결률입니다.

학습 분야마다 난이도와 표본 수가 다릅니다. 낮은 값이 곧 개인의 낮은 능력은 아닙니다.

03 / HINTS

힌트 뒤의 새로운 시도

각 실행의 첫 힌트보다 늦게 시작한 바로 다음 시도를 확인합니다. 성공·실패만 평가 분모에 넣습니다.

힌트를 사용 중이던 시도의 성공을 소급해서 연결하지 않습니다. 힌트 자체의 효과를 증명하지 않습니다.

04 / DURATION & RETRIES

오래 걸리는 풀이와 반복 시도

히스토그램은 해결 실행의 active_ms 분포입니다. 산점도는 active_ms가 있는 실행의 시간과 시도 수를 비교합니다.

일시정지는 제외합니다. 산점도는 최대 200개를 표시하고 좌표가 같은 기록은 겹칠 수 있습니다.

05 / FAILURES & ACTIVITY

반복 실패와 행동 시간대

operation_failed의 연산·원인 조합을 봅니다. attempt_failed와 이중으로 더하지 않습니다. 히트맵은 이벤트 발생 수입니다.

히트맵이 진할수록 이용자 수가 많다는 뜻은 아닙니다. 한 명이 반복 행동을 많이 했을 수 있습니다.

06 / VERSIONS

버전별 비교와 표본

같은 task_id의 content_version을 구분합니다. 막대·툴팁·원자료 표에서 실행 수를 함께 확인하세요.

서로 다른 사용자·기간·난이도 구성의 차이가 있습니다. 무작위 비교 실험 없이 개선의 인과 효과를 단정하지 않습니다.

07 / SCOPE

필터와 기간

문제 지표는 선택 기간에 시작한 실행을 현재까지 추적합니다. 행동 로그·히트맵은 선택 기간의 이벤트 발생 시각을 봅니다.

분야, 게임 실행 ID, source, 플레이어 검색, 문제, 버전을 적용합니다. 행동 유형 필터는 로그 탐색에만 적용합니다. 기본 기간은 최근 28일입니다.

08 / DATA QUALITY

비어 있는 데이터도 정보입니다

결과가 없으면 비율은 미정으로 표시합니다. 이전 형식 이벤트는 원본 조회가 가능하지만 문제·시도 지표에서는 제외합니다.

이벤트가 없다는 사실만으로 힌트 미사용이나 실패 없음으로 단정하지 않습니다. 완료 결과가 아직 오지 않았다면 해결률 0%는 학습 실패를 의미하지 않습니다. UI를 채우기 위해 실제 출처의 가짜 로그를 만들지 않습니다.

09 / GAME CATALOG

4개 분야 · 24종 게임

자료구조 10종, 알고리즘 6종, SQL 4종, 데이터 탐색 4종입니다. task_id가 보고서 실행 ID와 일치할 때 분류하며 영문 대소문자만 정규화합니다. 제목이나 기존 주제로 추측하지 않습니다.

DS09는 트리 구조, ST06은 트리 순회입니다. DS10은 그래프 구조, ST09는 그래프 탐색입니다. 미분류 기록은 전체 지표에는 포함하고 별도 목록으로 표시합니다.

10 / OPERATION VS COMPLETION

연산 성공과 문제 완료

연산 성공은 행동 하나의 성공입니다. 문제 해결률은 completed 실행 / 전체 시작 실행이며 진행 중과 포기도 분모에 포함합니다. 연산 성공만으로 문제 완료를 추정하지 않습니다.

평균 풀이 시간은 완료된 실행 중 active_ms가 있는 기록만 집계합니다. 누락된 시간을 0초로 채우지 않습니다. 게임별 오답·되돌리기·별점은 필드 계약이 확정되기 전 추정하지 않습니다.
